## Material findings and evidence

1. **Semgrep false-clean (OBSERVED, confidence 0.95, BUILD).** At baseline
   `f501074`, mocked `exit 2 + {results: [], errors:[...]}` and `exit 0 + {}`
   returned `success` with zero findings. Official Semgrep docs define exit 2
   as failure and exit 0 as no errors (unless `--error` is used). The fix now
   requires exit 0/no signal/valid results/empty errors, fails malformed or
   partial completion, and retains valid parsed findings from failed output.
2. **Security response ambiguity (OBSERVED, confidence 1.0, WATCH).**
   `pi-security-engine.ts` accepts malformed discovery as empty and the
   orchestrator can remove severe candidates after malformed confirmation.
   Existing exceptions preserve candidates; explicit true/false answers work.
   A strict verdict ledger is a security policy decision, not silently folded
   into the scanner patch.
3. **Execution-boundary gap (SUPPORTED, confidence 0.95, WATCH).** The
   security CLI fallback uses bare Pi with inherited environment; Semgrep is
   PATH-resolved. The normal Pi harness has tighter restrictions, but no
   complete trusted-binary/filesystem/network policy is proven. No exploit or
   credential was executed/read.
4. **Dependency advisories (OBSERVED, confidence 0.95, WATCH).**
   `pnpm audit --prod --json` reports 15 advisory entries (3 high, 10
   moderate, 2 low) in transitive Octokit/Undici packages. High entries concern
   Undici WebSocket behavior not shown to be used by this action; presence is
   not reachability. No upgrade was made.
5. **Quality/release evidence (OBSERVED, confidence 1.0).** Baseline passed
   48 files/438 tests; after the fix, 49 files/452 tests pass, typecheck,
   Biome, both ncc builds, bundle syntax and expected non-PR smoke exits pass.
   This does not establish live LLM precision, competitive quality, or a
   successful consumer rollout. Coverage remains uneven (CLI/security
   publisher paths are materially less covered).
